Stage 4b · out-of-distribution test

Leffa Runbook

Getting a virtual try-on running on a free GPU, and finding out whether it can handle a kurta. About two hours the first time, most of it waiting on downloads.

Not yet run end to end. These steps are written from Leffa's published API and its app.py, not from a completed run on your account. Expect at least one thing in setup to need fixing — the “when it breaks” section covers what usually does.

Kaggle or Colab

Both are free and both work. For this job the difference is real.

Kaggle recommended

  • 30 GPU-hours/week, guaranteed and reset on schedule
  • 9-hour sessions, no idle babysitting
  • Checkpoints attach instantly as a dataset — download once, ever
  • Environment is pinned, so detectron2 builds more reliably

Colab

  • 15–30 GPU-hours/week, dynamic and unpublished
  • Disconnects after ~90 minutes idle — can cost you the 10 GB download
  • At peak times a GPU request may quietly return CPU
  • Drive's free 15 GB is tight against ~10 GB of weights

You do not have to choose permanently. Running both gives you roughly 60 free GPU-hours a week. Start on Kaggle; keep Colab for when the weekly quota runs out.

The steps

1

Create the account and turn on the GPU

5 minutes · one time

On Kaggle you must verify a phone number before GPUs unlock — this catches people out, since the accelerator menu appears but never allocates until you do. Then in a new notebook: Settings → Accelerator → GPU T4 ×2, and Internet → On.

On Colab: Runtime → Change runtime type → T4 GPU.

2

Photos — you don't need any

0 minutes

Leffa ships its own example people and garments under ckpts/examples/, and they arrive with the checkpoints in step 6. Nothing to upload, nothing to keep private.

This is not just convenient, it is the better experiment. The inpainting region comes from SCHP parsing the person plus garment_type — whether that region stops at the waist has nothing to do with who is in the photograph. So the truncation prediction is fully answerable on stock images, and using them removes ethnicity as a confound while you isolate the garment.

Later, if you want. Set USE_OWN_PHOTOS = True to check the model holds up on South Asian full-body shots specifically. Use your own or ones you have explicit permission for, keep them out of git, and note that a body photo in a public repo history is not something you can take back.
3

Get your code where the notebook can see it

10 minutes · one time

The notebook imports fabric_advisor.render, so the repo has to be reachable. Push it to GitHub, then either clone it in Colab or attach it as a Kaggle dataset called fabric-advisor. 

cd c:\Users\subha\OneDrive\Desktop\clothing
git init
git add .
git commit -m "Fabric advisor: verdict engine and flat-lay synthesis"
git remote add origin https://github.com/YOUR_USERNAME/clothing.git
git push -u origin main

In the Colab cell, replace YOUR_USERNAME with your GitHub handle. A .gitignore for .venv/ and data/cache/ is worth adding first.

4

Paste the cells

3 minutes

Open scripts/kaggle_leffa_ood.py. Each # %% marks one notebook cell — paste them in order into separate cells. The first cell detects whether it is on Kaggle or Colab and sets its paths accordingly, so the same script works on both.

5

Install — this is the step that fails

15–25 minutes

Leffa needs detectron2 for DensePose. It is not on PyPI and compiles against whatever torch is installed, which is exactly why it breaks: Colab's preinstalled torch tends to run ahead of what detectron2 supports.

The cell asserts detectron2 imported successfully and stops if it did not. That is deliberate — failing loudly here is much better than discovering it 20 minutes into a run.

6

Download the checkpoints

15–30 minutes · ~10 GB

Try-on weights plus SCHP, OpenPose and DensePose preprocessors. On Colab these land in Drive so a disconnect does not cost you the download twice; on Kaggle, once it finishes, save the output as a dataset and attach that next time instead of re-downloading.

Do this while you are watching. On Colab especially — a 90-minute idle disconnect mid-download is the most common way this step is wasted.
7

Run it

~30 seconds per image

Cell 2 synthesises kurta flat-lays from four fabric prints. Cell 4 varies two things, one at a time:

  • garment_type — upper_body against dresses. This is the experiment: it decides whether the kurta problem is a masking bug you can fix today or a model limitation needing retraining.
  • condition — control uses a Western top Leffa was actually trained on; kurta uses your synthesised flat-lay. Without the control a bad result is ambiguous, and you cannot tell a garment-category problem from a broken setup.

Four people × five garments × two types = 40 generations, so budget about 20 minutes. Cut people[:4] to people[:1] for a first pass, to confirm the pipeline runs before spending quota.

8

Read the report

10 minutes

Cell 5 writes ood_report.csv. The column that settles the question is mask_bottom, grouped by garment_type.

What the numbers mean

mask_bottom ≈ 0.45
on upper_body,
higher on dresses		 Prediction confirmed. The kurta problem is a masking bug, not a model limitation. Use dresses and move on. No retraining.
mask_bottom low

masks fine,

0.75–1.25		 The print is rendered at the wrong repeat size, so any verdict stated in centimetres is void for that image.

When it breaks

detectron2 will not build

The most common failure by a distance. Pin torch to the version in Leffa's requirements.txt, restart the runtime, then rebuild. Do not skip detectron2 — DensePose is required and Leffa will not run without it.

CUDA out of memory

A T4 has 16 GB. Leffa runs fp16 already. Lower steps from 30 to 20 and process one person at a time. If it still fails, restart the runtime — a previous cell is probably still holding the model.

Colab disconnected and everything is gone

Expected on free Colab. This is why checkpoints cache to Drive. Re-run the setup cells; the download step will skip and symlink the cached weights.

"No GPU available"

On Kaggle, check your weekly quota on the account page. On Colab there is no quota to check — wait a few hours, or switch platforms. This is the concrete cost of Colab's undisclosed allocation.

Parsing finds no person

The photo is probably not full-body, or the pose is unusual. SCHP expects a standing, front-facing figure. Crop tighter to the person and retry.

After it works

Two things follow, in this order. First, replace the garment template: photograph a plain light-grey kurta once, derive mask, shading and displacement from it, and the same compositing code produces photographic drape instead of the current procedural silhouette. Second, write down what failed. A documented known-failure list is worth more in an interview than a reel of cherry-picked wins, and it is what separates an engineer from a demo.

One licensing thing to be clear-eyed about

Leffa's code is MIT, which is why it was chosen over CatVTON and IDM-VTON — both CC BY-NC-SA and non-commercial only. But its released checkpoints were trained on VITON-HD and DressCode, and VITON-HD is CC BY-NC 4.0.

Whether trained weights inherit a training set's non-commercial restriction is genuinely unsettled, and anyone who tells you it is settled in either direction is overstating. For a portfolio project it does not matter. Before you put affiliate revenue behind it, get a real answer — that is a question for a lawyer, not for a model card.
